# 旧版三个眼科智能体复盘与当前改进

## 复盘范围

参考项目：`/Users/qizs/conclusion/灵瞳系统重构/OphAgent`

只复盘病灶定位、辅助诊断和报告生成。旧版智能问答与眼科知识库未作为插件参考，因为问答、知识库检索和按需联网检索已经是 OphAgent-Pro 的默认能力。

## 可保留的产品价值

| 旧版智能体 | 有价值的输出方式 | 当前实现 |
|---|---|---|
| 病灶定位 | 原图叠加矩形区域，区域列表与图像对应 | 保留原图框选；只显示通过 `ImageRegion` 校验且确实来自模型的坐标 |
| 辅助诊断 | 候选项分卡展示，可展开查看依据 | 改为定性鉴别；逐项显示支持、反对、缺失信息，不把模型分数称为患病概率 |
| 报告生成 | 结构化 Markdown，可复制、编辑和导出 | 按实际检查模态生成；自动进入可编辑产物工作区，支持 MD、PDF、DOCX、JPG |

## 不应继承的问题

### 病灶定位

- 旧版在模型未返回置信度时默认补成 `0.9`，会制造虚假确定性。
- 坐标契约不清晰，没有稳定区分像素坐标与归一化坐标。
- 单一红框和百分比容易被误解为经过验证的诊断结果。

当前约束：

- 缺失置信度保持“未报告”，不补默认值。
- 坐标必须声明 `pixels` 或 `normalized`，并通过边界校验。
- 前端使用“模型定位把握度”的定性标签，不将其解释为疾病概率。
- 模型无法可靠定位时返回空区域，系统明确说明没有补造坐标。

### 辅助诊断

- 旧版强制输出 3–5 个诊断和数值百分比，会鼓励凑数和伪概率。
- 推理文字没有区分图像观察、临床事实、指南证据和缺失信息。
- 候选诊断与证据来源之间没有稳定引用关系。

当前约束：

- 候选数量由资料决定，允许为空。
- `confidence` 仅表示当前资料的 `low / medium / high` 支持程度。
- 每项鉴别必须分别记录支持、反对、缺失信息。
- 鉴别节点消费 `ClinicalState`、影像观察、文档解析和已检索证据；证据 ID 必须来自真实检索结果。

### 报告生成

- 旧版直接展示 `<think>`，泄露未经整理的模型内部推理。
- 报告模板写死眼底结构，面对 OCT、角膜地形图等模态会产生错位内容。
- 检查日期、影像类型等缺失字段可能被模型自行补齐。

当前约束：

- 只显示公开阶段摘要、关键动作和关键结果，不显示私有 chain-of-thought。
- 报告模型必须根据输入识别检查模态；无法确定时标为“未提供”。
- 报告依次整合检查资料、可见观察、临床印象、鉴别与依据、局限和建议。
- 报告产物可编辑、实时预览并导出。

## 自动调用与组合规则

| 用户输入特征 | 自动能力组合 |
|---|---|
| “什么是青光眼”“查指南/来源” | 默认问答 + 本地知识检索；必要时联网检索 |
| 上传影像并要求“标出/定位/框出” | 病灶定位 |
| 要求“异常是什么/鉴别/评估/下一步” | 辅助评估；有影像时同时运行影像观察 |
| 上传影像并要求生成报告 | 影像观察 + 辅助评估 + 报告生成 |
| 用户显式选择多个插件 | 合并为一个依赖图，共享临床状态、影像观察和证据，避免重复调用 |

执行结果通过统一 `PlanNode.output` 进入最终合成：定位节点提供经校验区域，辅助评估节点提供结构化鉴别，报告节点消费两者并生成可编辑产物。这样插件不是彼此隔离的页面模式，而是主智能体可以按任务需要组合的专业能力。
